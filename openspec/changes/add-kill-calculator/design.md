## Context

See `proposal.md` for motivation and `specs/mechanics-pages/spec.md` for the reader contract. Before this change, `packages/publication/src/mechanics.ts` picked one alphabetically first fixed-level creature as a static kill example, and `packages/contracts/src/public/documents.ts` exposed only that example. The Character Progression curve, level control, step guide, quest and skill information, and Heroic Tier settings already have published data paths. Creature records carry experience bounds, level, and lower/higher modifiers. Published NPC pages and place relationships provide linkable refs. Reuse those paths instead of another capture, separate rules database, or hard-coded build setting.

Before this change, `apps/site/src/lib/detail/pages/CharacterProgressionPage.svelte` rendered the example and `LevelCurve` in separate sections, while `apps/site/src/lib/detail/sections/LevelCurve.svelte` owned its slider level internally. Lift the selected character level to the page and bind it into `LevelCurve` as well as the calculator so a change to either control updates the chart marker, level totals, and modeled kill count without adding a second disconnected level selection.

The source of truth for the kill rules is build 25434619, `local/mechanics-rules-25434619-placements.json:195-232,235-372,606-645`. Its evidence registry resolves `ghidra-progression` to `research/ghidra/25434619/progression-functions-20260928.json`, `native-rounding` to `research/progression/25434619/rounding-disassembly-20260930.json`, `native-constants` to `research/progression/25434619/native-constants-20260929.json`, `probe-virtual-slots` to `research/progression/25434619/progression-virtual-slots-20260929.json`, and `direct-callers` to `research/progression/25434619/direct-callers-20260929.json`. `research/ghidra/25434619/progression-native-methods-20260928.json` identifies the native signatures, including `GameModifierManager.GetValueAfterGameModifier` returning `Single` and `LevelingManager.AddCharacterEXP` accepting `Int32`. The decompilation is evidence, not reconstructed game source; the published rule phrases and call-site disassembly bound the claims below.

## Goals / Non-Goals

**Goals:**
- Publish a build-specific, fully linked selection of eligible creature-level inputs in the Character Progression document and render a calculator that shares the curve's selected player level.
- Trace every displayed modeled stage to an identified native call; preserve the unresolved stages visibly rather than fabricating the game's exact final award.
- Show whole kills to advance from zero experience at the selected level, using the already-published level template.

**Non-Goals:**
- Reverse-engineering or guessing which game modifiers apply, active world modifiers, saved current experience, active companion state, or actual Heroic status of any published creature; the Heroic control is hypothetical.
- Changing authored NPC facts, quest or skill rewards, the level-curve chart, or the Heroic Essence model.

## Decisions

### Project only eligible, published source records

Replace the single `KillExampleSchema`/`example` with `CharacterProgression.killCalculator: { groups: { place?: EntityRef; name: string; creatures: { creature: EntityRef; level: number; minExperience: number; maxExperience: number; lowerModifier: number; higherModifier: number }[] }[]; defaultCreature: EntityRef; heroicMultiplier?: number }`. Select only a published creature page with non-scaling, single fixed level, known nonnegative min and positive max experience (max >= min), and both known numeric lower/higher percentage modifiers. Resolve the source to its published NPC page; use the published NPC locations and linked published place refs to group it, deduplicating repeated same-creature/same-place memberships but retaining a creature in each genuinely distinct place. Retain eligible published creatures without a published place under `Other` rather than discarding them. Choose the default deterministically from this set, not from an invented source, and fail publication if the required default cannot be formed. Read Heroic kill multiplier from captured, published Heroic Tier settings if available; omit the optional field and corresponding control when it is unavailable. Never replace a missing modifier or setting with zero or a guessed default. An NPC variant must use its own authored record's level, bounds, and modifiers, rather than inheriting another variant's values.

`packages/publication/src/index-resources.ts:183-186` currently passes published keys and spawned levels to mechanics projection and already holds the projected entity documents; extend its mechanics projection inputs with actual published NPC pages/place membership rather than guessing a scene from raw NPC records. Keep a single publication-owned document, linked to accepted references, with the same schema/version migration and graph validation as other mechanics documents. The Heroic page remains the source of the multiplier, not a second copy of its literal build value in the site.

### Follow the native kill pipeline, but stop before unknown modifications

The actual native sequence is **not** "multiply a rolled value by all modifiers and round once":

1. `LevelingManager.GenerateMobEXP` calls the `UnityEngine.Random.Range(int,int)` overload on NPC `MinEXP` and `MaxEXP` without incrementing the upper argument (`research/progression/25434619/rounding-disassembly-20260930.json:211-229`; the probe identifies the overload). The possible whole rolls are `[min,max)` and a matching pair yields `min` (`local/mechanics-rules-25434619-placements.json:235-267`). Model the endpoints as `min` and `max-1`, or `min` when equal; do not present max itself as possible except for that equal-bounds case.
2. `GameModifierManager.GetValueAfterGameModifier` changes the random roll and returns `float`; then `GenerateMobEXP` converts the result with `iVar10 = (int)fVar13`, truncating toward zero **before** any level comparison. Which game modifiers apply and how much they change the float remain unknown (`research/ghidra/25434619/progression-functions-20260928.json:18-26`, `local/mechanics-rules-25434619-placements.json:269-289`). The calculator shows an explicitly modeled scenario without that unknown change; it must not call its output a guaranteed in-game interval.
3. Compare the creature's level with the player's level, using that creature's authored modifier. For a creature above the player, native `iVar10 = (int)((float)(int)fVar13 * (higherModifier / 100.0f)) + (int)fVar13`; for a creature below, native `iVar10 = iVar10 + (int)((float)iVar10 * (lowerModifier / 100.0f))`; for equal levels, no percentage contribution. Thus **the contribution**, not the sum, is cast to int/truncated toward zero at this step; do not substitute a nearest-int, floor for negative numbers, or a single late cast. The 100.0 divisor is `research/progression/25434619/native-constants-20260929.json:6-12`; the direction and source fields are in `local/mechanics-rules-25434619-placements.json:291-319` and `research/ghidra/25434619/progression-functions-20260928.json:18-26`.
4. For a selected Heroic kill with an available published setting, `HeroicTierManager.ApplyKillExperience` multiplies the level-adjusted integer by the captured `float` multiplier and rounds to a whole number, with halfway ties going to the even integer. The native tail jump at `research/progression/25434619/rounding-disassembly-20260930.json:77-142` enters the analyzed rounding routine at `:145-209`; the rule sources are `local/mechanics-rules-25434619-placements.json:321-345,606-644`. This rounding applies **only** to the Heroic stage; it is not a license to round other stages.
5. `GenerateMobEXP` counts living followers of the eligible companion/adventurer kinds and divides the Heroic-adjusted `int` by `count + 1` with integer division before passing it to both `AddCharacterEXP` and weapon-template experience. This truncates toward zero, hence rounds down for nonnegative kill experience. The companions do not receive separate shares (`research/ghidra/25434619/progression-functions-20260928.json:18-26`, `local/mechanics-rules-25434619-placements.json:347-371`). The UI takes zero to ten *living followers*, not a character party size, and labels the modeled player share rather than claiming each follower gets the remainder.
6. `LevelingManager.AddCharacterEXP` then multiplies a positive Experience Bonus total as a percentage, subsequently multiplies by the **active world modifier**, and casts its float to an integer for the actual character award. This is a separate post-split stage, not another int cast within the kill formula (`research/ghidra/25434619/progression-functions-20260928.json:9-17`, `local/mechanics-rules-25434619-placements.json:195-232`). Model the user-entered nonnegative Experience Bonus with the split amount `amount * (1 + bonus / 100)`; leave that estimate **unrounded** because the unknown world multiplier follows it. The game might convert the final award to an integer once after the world multiplier. Do not show integer bonus-stage results or claim exact experience earned without knowing that multiplier. At level cap the game stops awards (`local/mechanics-rules-25434619-placements.json:163-177`); the calculator suppresses next-level kill estimates there.

Calculate min/max over the authored possible integer rolls with each known stage in this order, rather than assuming max-experience is an inclusive roll. Display a direct explanation of which level modifier and Heroic/split/bonus stages were used and the precise caveat **“World modifiers and some game modifiers are not included.”** Show the linked creature facts beside the result and full-width controls above them. Give the curve and calculator one selected-level state. For a fresh selected level below cap and positive estimates, show `ceil(toNext / maxModeledAward)` through `ceil(toNext / minModeledAward)` whole kills; if an endpoint is zero, show no finite count for that endpoint. Label **“Kills to next level from 0 experience”**, not progress toward the next level of a saved character. At cap, omit the count.

## Risks / Trade-offs

- A native modifier can alter the random roll before level adjustment, and the world multiplier and final integer conversion follow the positive bonus. The modeled range therefore is conditional, never a guaranteed in-game award; the caveat must remain beside the numbers.
- The native pipeline uses single-precision float in game, while browser arithmetic is double precision. The design fixes proven stage boundaries and nearest-even Heroic rounding, but does not fabricate bit-for-bit equivalence at unstable float boundaries or claim exact final awards.
- Filter only records with all required authored numeric fields. Missing fields are evidence gaps, not zero; the unplaced group keeps reachable published creatures without known place links.
- Keep narrow-screen stacking and stable search/level controls so the calculator does not make the existing chart or other guide steps inaccessible.
