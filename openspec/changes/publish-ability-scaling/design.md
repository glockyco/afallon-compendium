## Goals / Non-Goals

**Goals:**
- Publish each applicable coefficient and stat as a typed, linked rank relation and preserve distinct flat/weapon operands through all public surfaces.
- Build reverse navigation from stats to effects and their player/creature ability applications without broadening excluded/unreachable pages or joining wrong versions.
- Register same-build rule evidence for guide behavior, with tooltip probes as bounded corroboration; verify exact Assassin browser scenarios and periodic distinctions.

**Non-Goals:**
- A universal combat simulator or fixed player/creature damage number; defense, hit, crit, random weapon roll, target modifiers and changing current stats prevent a guaranteed hit from these operands.
- Reclassifying Magical attacks from a custom Slicing label; treating skill modifiers as stats; deriving healing-stat scaling from custom healing labels rather than altered-stat IDs; evaluating unknown weapon loadouts by guesswork.
- Claiming that the periodic tooltip experiment observed actual later pulse values; it measured tooltip calculations while native pulse code establishes recalculation.

## Decisions

1. **Derive scaling once from canonical stat definitions at catalog normalization.** Build an index of bonus rows by main damage type and by HEALING's altered-stat target ID; additionally index GLOBAL_HEALING by the configured HealthStatID. For each supported effect rank create separate typed `ProgressionEffectScaling` entries (`damageType`, `healing`, `globalHealing`, `explicit`) with the referenced stat and `modifyValue * 100` or explicit modifier percentage. Do not collapse contributions from the same stat but different sources; do not use `customDamageType` to override main damage type or `customHealingType` to filter HEALING entries. Health-target Potion healing still receives matching HEALING and GLOBAL_HEALING entries. Respect `flatCalculation` for implicit sources only. Guard unsupported enum/missing stat/HealthStatID evidence, preserving all other rank fields and coverage issues. Reuse indexed definitions across ranks rather than rescanning every stat for each rank. Correct `skillModifierSkill` identity and update any callers of the wrong mapped property in the same cutover.

2. **Keep a structured public rank model and derive summaries from it.** Extend the strict versioned public effect contract with linked scaling entries and contextual weapon selection/percentage; keep authored base and other rank actions intact rather than replacing them with a synthetic total. Propagate the selected effect-rank projection into the relevant ability version using its existing `appliedEffects` association and rank/target/chance, not by matching effect names. The effect detail and tooltip, ability primary/secondary presentation, and short list previews read the same projected facts. Existing snapshots lacking optional scaling can still render base/weapon operands without interpreting absence as a verified zero. The public schema must reject malformed coefficient/reference/source entries.

3. **Project reverse uses with reachable source identity.** In `documents/stats.ts` or one reused relation projection, index effect rank contributions by stat key and join applying abilities by the existing effect source/version relation, including creature ability users. Output distinct effect-rank references plus player/creature application context, not the creature's own current stat or a grant source. Respect exclusions and unresolved links (plain text/non-dead references); deterministic deduplication and reasonable grouping prevent large-page duplication. Do not add irrelevant abilities that only check an effect or apply a different rank.

4. **Explain rules with qualified evidence.** Add verified rule entries to the registered Combat mechanics record referencing native function outputs and runtime tooltip probe artifacts as external/ignored evidence, then project player-language explanations with links and carefully scoped numeric tooltip examples. The guide distinguishes type match, additional explicit modifier, flat bypass, weapon roll context, and per-pulse live-stat lookup. Preserve existing guide sections and existing applicability/chance wording; no blanket promise of real damage or all-tick totals.

## Risks / Trade-offs

- **Custom and enum names can be misleading** → match native identifiers, not player-facing label similarity; a Magical Slicing attack scales from Magical's stat.
- **A missing stat definition or category can look like zero scaling** → mark it unavailable/partial and keep authored amount, weapon modifier, other known contributors and a coverage issue.
- **Repeated joins can inflate stat pages and duplicate effect contexts** → index once, dedupe by effect/rank/ability/version and aggregate sources; keep compact lists and existing deferred secondary display.
- **Tooltip rounding and live calculations differ** → preserve coefficients unrounded, quote exact observed Assassin tooltip totals only as tooltip examples, and test coefficient relationships independently of incidental rounding.
- **Periodic damage might have additional per-pulse modifiers** → document only verified stat recalculation and selected-weapon context, not complete pulse totals.
