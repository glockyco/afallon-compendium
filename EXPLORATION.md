# Afallon research reference

This file records game and data facts for the accepted Afallon build, Steam build **25653798** (0.16.3). Each topic names its evidence and its limits. Runtime and native-analysis procedures live in `.agent/skills/hotrepl-runtime-inspection/SKILL.md` and `.agent/skills/native-analysis/SKILL.md`. Operator commands live in `README.md`. Requirements and design decisions live in `openspec/specs/` and `openspec/changes/`. Commit bodies explain why changes exist. Code comments cite rules near their implementation. Superseded observations are not a second source of truth.

## World model

### Scenes and arrivals

- A build scene, a database `RPGGameScene`, a loaded Unity scene, and a rendered map space are distinct. The scan inventory keeps build settings, database scene records, destinations, loaders, and component queries. A currently loaded scene does not prove that every scene is reachable or scanned. Evidence: `packages/scan/src/probes/collectors/world-inventory.csx`, `packages/scan/src/collectors.ts:190-237`.
- A teleport names an `RPGGameScene` record, and a scene load passes the `entryName` of that record to Unity. `LoadingScreenManager.LoadGameScene` first maps records 3, 9, and 11 to Coalway outdoors (47) through `CoalwayOutdoorsMigration.ResolveSceneID`, and it returns without a load when the record does not exist. Its `AsyncLoad` coroutine passes the `entryName` to `SceneManager.LoadSceneAsync`. Effect teleports use the rank `gameSceneID` through `RPGBuilderEssentials.TeleportToGameScene`, and game action teleports use `GameSceneID`. In build 25434619, `Application.CanStreamedLevelBeLoaded` is true for the entry names of 30 of the 42 records and false for the other 12. This probe did not load any scene. Evidence: ignored `research/ghidra/25434619/scene-load-functions-7-20260929.json` and `research/item-sources/25434619/scene-loadability-20260929.json` in the main checkout.
- In build 25434619, a later native scene entry can reuse the character's last position. A stale saved position can lie outside the destination and cancel the entry. A visit uses `TeleportToGameScene` at the planned doorway from a discovered world teleport. A scene without such a doorway uses its authored start position. The selected doorway is part of the visit evidence. An authored start is not necessarily inside the map zone. Evidence: `packages/scan/src/probes/scene-visit/support.csx:57-95`, `tools/update/author-scan-arrivals.ts`. This does not prove that all starts are safe for map capture.
- `ChunkHider` can deactivate distant terrain chunks and their loaders. A stream visit can hold a chunk at its target position, preload its source, then release the hold during restoration. Loader presence does not mean that its root is loaded or render-ready. Evidence: `packages/scan/src/probes/stream-visit/support.csx:47-80`, `packages/scan/src/probes/stream-visit/traversal.csx:70-130`.

### Map spaces and geometry

- Map-space membership uses reviewed scene bindings, a horizontal frame, and membership domains. World Y remains an observation and does not choose the imagery layer. A position outside the domains remains unresolved instead of being moved to the nearest map. Evidence: `packages/contracts/src/spatial/map-spaces.ts`, `packages/catalog/src/placements.ts:27-48`.
- Native `MapZone` observations record a texture, collider, and coordinate calibration. Geometry observations include renderers, terrain, navigation surfaces, and landmarks. A zone's bounds, a texture's name, and a navigation triangulation are not proof of a complete playable or captured boundary. Evidence: `packages/scan/src/probes/collectors/map-geometry.csx:40-155`, `packages/contracts/src/spatial/map.ts`. Unity's [CalculateTriangulation reference](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/AI.NavMesh.CalculateTriangulation.html) excludes off-mesh links.
- Publication applies reviewed world offsets and folds game map icons into placements. The default imagery layer must be a game map. Captured terrain is a separate optional layer. Evidence: `packages/publication/src/map-shards.ts:327-375`, `packages/contracts/src/public/graph.ts:37-77`, `README.md` **Data pipeline**. A map layer does not certify source or screenshot coverage.

### Placements, producers, and identities

- Canonical database records, authored sources, physical placements, and current runtime instances have different identities. The placement resolver matches serialized scene and loaded-prefab provenance to a native component slot. Runtime instance IDs, hierarchy paths, names, and coordinates are observations, not persistent keys. Ambiguous matches remain unresolved. Evidence: `packages/scan/src/placement-identities.ts`, `packages/scan/src/scene-identities.ts:246-282`, `packages/scan/src/placement-roles.ts:33-84`.
- Multiple source components and roles can share one physical placement. Roles retain a source ID and an evidence pointer. An unplaced source keeps its facts without receiving a guessed placement. Evidence: `packages/scan/src/placement-roles.ts:87-124,126-158`, `packages/scan/src/collectors.ts:221-237`.
- `NPCSpawner` candidate lists and `OreSpawner` resource producers describe possible content, not only live NPCs or `CurrentNode` instances. An `OreSpawner` can refer to Herbalism, Mining, or Fishing through its authored skill and resource. Do not classify every such component as mining. Evidence: `packages/scan/src/probes/collectors/npc-producers.csx`, `packages/scan/src/probes/collectors/world-sources.csx:185-320,1250-1310`. No live instance is required to retain an authored producer.
- The loaded prefab index covers source-bearing prefabs that the scan loads. A skipped or inactive stream does not prove that its content is unused or unreachable. Evidence: `packages/scan/src/scene-identities.ts:282-350`, `packages/scan/src/probes/stream-visit/traversal.csx`. Full-world streamed geometry needs separate evidence.
- The game can destroy a scene object at run time. Each later sibling then has a runtime sibling index one lower than its serialized index. The resolver matches such a child to the one later serialized sibling that has its name, and two or more such siblings leave it unresolved. Before this rule, the Ice cave 1 chillwind scan lost 25 placements after the destruction of `QUESTS & TRIGGERS/Remove slow key check`. Evidence: `packages/scan/src/placement-identities.ts` `serializedChild`, scan run `53ed07e1-f073-43e3-a5ad-df7575df40ba` target `build-scene:44`.
- A `CountdownDestroyer` (`countdownTime`, `Update`) destroys its object a fixed time after the scene starts. Thirteen scanned scenes of build 25434619 hold such objects. A scan that reads the scene late therefore records fewer objects. The collectors read the scene evidence before the artwork collector, which takes thousands of frames. The scene 44 rescan read world sources 135 frames after the visit started and recorded all 142 sources of the accepted scan. Evidence: `packages/scan/src/collectors.ts` `ARTWORK`, recovered `CountdownDestroyer.cs` in the main checkout, scan runs `f689e489-a62d-4fdb-8949-bf0627e8362a` and `87bcfce0-9b03-4df5-9ebb-a613cdaa2b9d`.

### Roles, availability, and conditions

- NPC service roles depend on authored merchant and quest flags. Faction disposition depends on player state. A producer's faction override suppresses base-faction disposition until its application is verified. Action references, not component names alone, determine container and quest-location roles. Evidence: `packages/scan/src/faction-roles.ts`, `packages/scan/src/placement-roles.ts:126-158`, `packages/scan/src/world-roles.ts`.
- Availability, reachability, extraction, and imagery are separate coverage states. An inactive component can be an authored source. A loaded addressable owner does not prove its geometry is ready. An existing game texture does not prove project-owned terrain coverage. Evidence: `packages/scan/src/collectors.ts:259-320`, `packages/scan/src/scene-streams.ts`, `packages/capture/src/capture-readiness.ts`.
- Requirement probes retain authored condition fields. A resolved reference does not verify nested selector or object-backed requirement behavior. Evidence: `packages/scan/src/probes/collectors/conditions.csx`, `packages/catalog/src/conditions.ts`. Do not infer eligibility from a template name or the presence of an ID alone.
- An Effect requirement tests one effect by ID. `State.Active` needs the effect, and `State.Inactive` inverts the test. Only when `BoolBalue1` is set does the game compare the effect's stack count with `Amount1` through `Value`: `Equal` needs exactly that count, and `EqualOrAbove` needs at least that count. `Comparison` is not read. All effect-280 ("Stacking effect done") requirements of the `N invader killed` templates set the flag. The native code does not show which action adds the stacks. Evidence: `research/ghidra/25434619/effect-requirement-native-map-20260927.json`, `research/ghidra/25434619/effect-requirement-assembly-20260927.txt` in the main checkout, `packages/catalog/src/queries.ts` `requirementSpans`.

Otherwise the current scene's `ZoneScalingMinLevel` and `ZoneScalingMaxLevel` apply. Evidence: build-25434619 `npc-level-functions.json`, `packages/scan/src/probes/collectors/canonical.csx:919-921`.

## Loot and merchants

- `RPGNpc.MerchantTables` holds current merchant bindings. The legacy `merchantTableID` is exported for evidence but does not replace the list. Table bindings retain their requirement templates, and stock rows retain authored currency and cost. These fields alone do not establish the player-visible modified price or eligibility. Evidence: `packages/scan/src/probes/collectors/relationships.csx:1-22,330-485`, `packages/scan/src/probes/collectors/canonical.csx:401-412`.
- Loot on a kill comes from `EconomyUtilities.GenerateDroppedLoot`, and only when `ShouldRewardPlayer` gives the player the reward credit. Each roll uses `UnityEngine.Random.Range(0, 100)` against a rate times `M`, the heroic-tier loot multiplier times the world modifier `DropRate`. Evidence: `research/ghidra/25434619/world-loot-functions-20260927.json`, `world-death-functions-20260927.json`, `world-chance-functions-20260927.json` in the main checkout.
- For each creature loot binding, the game checks the binding requirements and rolls the table: the roll passes through `GameModifierManager.GetValueAfterGameModifier`, is truncated to an integer, and must not exceed the binding rate. A rate of 50 therefore passes about 51 times in 100. The entries then roll in order. An entry needs the level band and `QuestItemDropAllowed`, which gives a quest-only item only during an ongoing gather task for it. A positive `LOOT_CHANCE_MODIFIER` stat increases the roll, so it lowers the pass chance. The table limit stops the pass. Then `PickMinimumDrops` fills up to the table minimum, never past the limit, by weighted picks without replacement among the eligible entries that did not drop, with weight `max(rate, 0.01)`. Evidence: the files above, `npc-loot-helper-functions-20260927.json`, `npc-world-roll-assembly-20260927.txt`, `npc-loot-minimum-weight-literal-20260927.json`.
- World loot comes from the bindings in `EconomySettings.WorldLootTables`. A binding reaches a creature of at least `MinimumWorldLootRank` (MOB, so every rank) whose level lies in `MinNPCLevel` to `MaxNPCLevel`, and 0 leaves a bound open. The table roll is a float roll without truncation. One kill gives at most `MaxWorldLootItemsPerNPC` (2) world items. The reference level is the creature's positive level, else the player level, else 1. A `LevelBandGear` table gives an item with a positive level requirement only to a reference level within 4 levels of that requirement (`EconomyUtilities.LevelBandRange`). Before a character's first gear drop, an item above the player level is also refused. Evidence: the files above, `world-loot-settings-20260927.json`, `packages/scan/src/probes/collectors/loot-rules.csx:83-121`.
- The Adventure Guide shows the authored entry rate as a percentage with one decimal. It ignores the table roll, the table limit, and the minimum-drop pass. Across the four Duskfall bosses, the displayed set matches the authored rates, and Thornmaw shows seven items at 15% although its table gives at most two. Evidence: `research/spikes/guide-drop-chance-result.json` in the main checkout.
- Publication therefore shows the guide value, the authored entry rate, as the chance of the item's own roll. The authored table roll below 100, the table minimum, and the table limit appear beside it. World loot rows name the creature levels that can drop the item. Publication does not claim an effective probability per kill, because the table roll, requirements, quest gates, level bands, limits, the world cap, and the minimum-drop pass change it. `LevelBandGear` creates dynamic gear, so a static entry list is not exhaustive. Evidence: `packages/catalog/src/queries.ts` `queryDropRows`, `packages/contracts/src/public/documents.ts` `DropRowSchema`.
- Resource ranks can link to loot tables. A missing `CurrentNode` does not erase the resource producer or its rank yields. Evidence: `packages/scan/src/probes/collectors/world-sources.csx:185-320`, `packages/scan/src/probes/collectors/relationships.csx:1258-1320`.

## Properties

- The canonical property record carries the income. Each `PropertyForSaleSign` reads the whole authored `RPGProperty` record, so the signs supply the type, the currency, and the purchase and sell prices. The catalog merges both sources and stops on a conflict. Evidence: `packages/catalog/src/world.ts` `signPropertyFacts`, `packages/catalog/src/normalize.ts`.
- `PropertyManager.Update` pays each owned property its income once every `EconomySettings.PropertyIncomeInterval` seconds of game time, which is 300 in build 25434619. A nonpositive interval stops the payments. A new manager starts a new interval, and the game pays nothing for time outside the game. Each payment adds the authored income in the property's currency, without a type check or a multiplier. Evidence: `research/ghidra/25434619/property-functions-complete-20260927.json`, `property-settings-20260927.json`, `property-constructor-assembly-20260927.txt` in the main checkout, `packages/scan/src/probes/collectors/relationships.csx` `propertySettings`.
- `BuyProperty` refuses an owned property, checks the purchase price in the property's currency, removes it, and records the ownership. `SellProperty` removes the ownership and gives the sell price in the property's currency when that currency is valid and the price is positive. Evidence: `research/ghidra/25434619/property-functions-complete-20260927.json`.

## Artwork

- Referenced sprites are read through a temporary render texture because the build's texture data is not CPU-readable. The collector reads each pixel rectangle, writes content-hashed PNG evidence, caches shared sprites, and restores temporary render state. Missing and unsupported sprites remain explicit. Evidence: `packages/scan/src/probes/collectors/artwork.csx:1-90`.
- Publication derives sized WebP artwork from the registered scan evidence. Sprite evidence is not a terrain capture or a calibrated map image. Evidence: `README.md` **Data pipeline**, `packages/contracts/src/public/graph.ts:22-29`.

## Map imagery and capture

- The game map is the default layer. Optional captured terrain requires a reviewed capture plan and separate readiness, raster, visual-restoration, and cleanup evidence. Capture does not infer coverage from `MapZone` bounds or a successful PNG encoding alone. Evidence: `packages/contracts/src/public/graph.ts:73-77`, `packages/capture/src/capture.ts`, `packages/capture/src/capture-readiness.ts`.
- Capture can set an explicit `clipHeight` for reviewed vertical cutaways. World XZ pixel registration and the source-to-map transform remain separate. A capture rectangle and clip height are not a complete playable boundary. Evidence: `packages/contracts/src/capture/evidence.ts`, `packages/capture/src/capture-planner.ts`.
- Tile readiness waits for intersecting streamed sources, stable frame evidence, and restoration. A timed-out load is a failure, not an empty tile. The configured world-surface readiness limit is 900,000 ms. Evidence: `packages/capture/src/capture-planner.ts:256-259`, `packages/capture/src/capture-readiness.ts`, `packages/capture/src/capture.ts:586-604`. A single captured tile does not establish full-world imagery.

## Publication measurements and limits

- A root JSON resource is limited to 65,536 bytes. A map, geometry, search, or kind-list part is limited to 524,288 bytes. An entity document is limited to 262,144 bytes. Root, coverage, imagery declarations, and map parts together must stay within 3,300,000 bytes. Optional geometry and imagery pixels are outside that accounting group. Evidence: `packages/contracts/src/public/graph.ts:11-35`.
- Publication checks map-space IDs, placement uniqueness, map-part identity, optional geometry references, default game-map imagery, and entity references. The selected build remains a preview because `coverageComplete` is false. Neither a successful publication graph nor a successful local stage proves complete supported-build source or imagery coverage.
